## Frontend y comandos

- El único manifiesto de paquetes está en `frontend/package.json`; el lockfile correspondiente es `frontend/package-lock.json`. Instala de forma reproducible desde `frontend/` con `npm ci`.
- Usa Node 24.20.0 (`.nvmrc`) y npm 11.19.0 (`packageManager`); `engines.node` restringe el frontend a Node 24.
- El arranque es `frontend/src/main.tsx` → `frontend/src/App.tsx`; las rutas `/ambulancia` y `/urgencias` muestran el flujo de ambulancia y el tablero de urgencias.
- El store Zustand (`frontend/src/store/useCases.ts`) se sincroniza entre pestañas del mismo navegador mediante `frontend/src/store/sync.ts` (BroadcastChannel y respaldo `localStorage`); no es sincronización entre dispositivos ni backend.
- Desde `frontend/`: `npm run dev` inicia Vite en el puerto `5173`; `npm run build` ejecuta `tsc -b` y luego Vite; `npm run lint` ejecuta `tsc --noEmit` (no hay script ESLint configurado).
- La integración de backend vive en `frontend/src/screens/local/LocalPortal.tsx`, ruta `/local`, y usa el proxy Vite de loopback configurado en `frontend/vite.config.ts`. No la conectes al store demo/localStorage.
- `npm run test:unit` ejecuta pruebas del extractor Mermaid y el manejo de errores con el runner integrado de Node.
- `npm run test:sync` requiere el servidor en `http://localhost:5173` (o `BASE_URL`) y Chromium de Playwright; verifica transmisión entre dos pestañas y no deja capturas.
- `npm run test:accounts` prueba localmente cuentas/urgencias con mocks sintéticos; `npm run test:system-admin` cubre alta, edición, baja y reactivación del panel global.
- `npm run test:units` verifica retiro/reasignación, filtro de institución/habilitación, baja confirmada e incertidumbre/logout durante CSRF con transporte sintético. El bloque B usa `expected_ambulance_id` obligatorio y null explícito para retirar; continuidad considera no terminales notificada/en_traslado/llegado. Arranque y aceptación manual en `docs/PRUEBAS_B.md`. Mantener orden usuario → unidad → asignación y bloquear solo la tabla objetivo en consultas relacionadas; Django `.exists()` elimina `OF` si no selecciona campos del modelo: usar `.first()` para esos bloqueos.
- B conserva revisión manual pendiente sobre `33909a7`. C requiere migración `audit/0007`: `record_pilot_closure` registra cierre global real (no ejecutar para ensayar en desarrollo); retención v2 conserva aplicación/auditoría sin cierre, luego 90 días/12 meses calendario, logs técnicos 30 días e idempotencia con su episodio. `AuditEvent` y `SessionRevocationEvent` comparten plazo de auditoría. Restauración real/purga requieren aprobación específica y destino aislado; wrapper exige `-ConfirmIsolated` más estado real independiente del snapshot. Ver `docs/PRUEBAS_C.md`. `ops/backups/tests/restore-postgres.tests.ps1` prueba guardias con dobles locales sin red ni restauración real.
- D agrega `emergencies/0005` y POST `update/`, `measurements/`, `measurements/rectify/` por episodio, con UUID/expected_version. Nuevas escrituras solo antes de recepción; replay ya confirmado conserva ámbito y no duplica. Originales de medición inmutables, rectificación one-to-one encadenada y motivo obligatorio; retenciónC desliga referencias únicamente dentro de la purga transaccional. Autor/fecha del triaje solo cambian si cambia la categoría; no atribuir legado al guardar notas. `npm run test:episode-updates` usa transporte sintético; `docs/PRUEBAS_D.md` incluye revisión manual pendiente. B sigue manual pendiente. BorradoresD en `PortalMemory.episodeDrafts`, sin persistencia web y sin rebasar versiones por refresh; guardar un formulario no descarta el otro.
- `npm run test:local-integrity` cubre la SPA con transporte sintético: respuestas perdidas, reintentos, expiración, cambio de ámbito y respuestas tardías. Requiere Vite; configura `BASE_URL` para el servidor de esta rama. No sustituye aceptación real entre dispositivos/backend.
- `npm run shots` requiere el servidor y Playwright, y sobrescribe capturas en `docs/screenshots/`. Captura `/local` y `/sistema` con mock sintético —no las rutas demo `/ambulancia` y `/urgencias`—; revisa README y las salidas nuevas después de regenerarlas.
